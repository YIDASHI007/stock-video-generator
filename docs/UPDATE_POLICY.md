# 桌面端更新规范

## 发布原则

1. 每个稳定版本必须同时发布完整包和相对上一稳定版本的增量包。
2. CI 打包前必须下载上一版完整包作为 Velopack 差分基线。
3. 若上一版基线下载失败或本次没有生成 delta 包，稳定版发布必须失败，禁止静默退化成全量更新。
4. 完整包始终保留，作为首次安装、跨版本跨度过大和增量校验失败时的兜底。
5. 客户端默认使用 Velopack 选择的 delta 链；只有差分不可用或重建失败时才回退完整包。

## 用户体验

- 更新提示必须展示目标版本、更新类型和预计下载体积。
- 下载界面必须区分“增量更新”和“完整更新”，并展示下载百分比、速度和剩余时间。
- 下载阶段不关闭当前服务；下载并校验完成后才停止后台服务、应用更新并重启。
- 取消下载不得关闭服务，也不得破坏当前安装。

## 发布检查

- `releases.win.json` 同时包含目标版本的 `Full` 与 `Delta` 资源。
- `*-delta.nupkg` 必须小于对应 `*-full.nupkg`。
- CI 必须通过后端测试、前端类型检查和生产构建。
- 正式 Release 必须上传 `RELEASES`、`releases.win.json`、full、delta、Setup 和 Portable 文件。
