# 社媒工作台全局界面规范

本规范是社媒工作台新增页面、功能和状态反馈的默认约束。目标是让信息在浅色、深色主题及不同显示器上都清楚可读，并避免页面自行拼装一套局部样式。

## 1. 设计令牌优先

- 页面只能使用 `styles.css` 中的语义令牌，不在业务组件里写状态色十六进制值。
- `--green` 是主操作/品牌色，不等于“成功正文色”。状态反馈必须使用 `--status-success-*`、`--status-info-*`、`--status-warning-*`、`--status-error-*`。
- 普通正文使用 `--text`，次要说明使用 `--muted`。`--faint` 只允许用于不影响理解的辅助信息。
- 浅色与深色主题都必须提供同名令牌；新增令牌时不可只补一个主题。

## 2. 全局提示

所有异步结果、页面顶部反馈和操作结果统一使用 `components.tsx` 中的组件：

```tsx
<SuccessNotice message="账号已添加。" />
<InfoNotice message="正在同步作品。" />
<WarningNotice message="Cookie 即将失效。" />
<ErrorNotice message="同步失败，请重新登录。" />
```

- 禁止在页面里手写 `notice ok-notice`、`notice info-notice` 等旧类名。
- 提示正文最小字号 13px、最小行高 1.5；不使用低字重或透明文字。
- 不能只靠颜色表达状态，必须同时有图标和文字。
- 普通状态使用 `role="status"` 与 `aria-live="polite"`；错误使用 `role="alert"`。
- 提示条需保留左侧状态边、图标底板和明确边框，确保灰阶环境下仍能分辨层级。

## 3. 可读性与对比度

- 正文与背景的目标对比度不低于 4.5:1；大号文字不低于 3:1。
- 图标、输入边框、焦点环等关键界面元素不低于 3:1。
- 任何浅色提示背景上禁止直接使用高亮荧光色作为正文色。
- 中文业务正文建议不小于 13px；只有序号、代码标签等非关键元信息可使用 11–12px。

## 4. 交互状态

- 可点击元素必须提供默认、悬停、键盘焦点、禁用和加载状态。
- 焦点使用 `:focus-visible`，不得无替代地移除浏览器焦点轮廓。
- 异步按钮在执行时禁用并显示进行中动词；完成后用全局提示反馈结果。
- 页面刷新、轮询和后台任务不得用静默状态变化代替用户反馈。

## 5. 新页面验收清单

提交新页面或新功能前，至少完成：

1. 浅色与深色主题各检查一次。
2. 浏览器 100% 与 125% 缩放各检查一次。
3. 键盘 Tab 可到达全部操作，焦点位置可见。
4. 成功、信息、警告、错误四种状态均使用全局提示组件。
5. 正文和关键元信息没有使用 `--faint` 或低透明度颜色。
6. `pnpm --filter @stock-video/web test` 与构建通过。

`check-design-system.mjs` 会阻止旧提示类名重新进入页面代码。若设计需要新增提示形态，应先扩展全局 `Notice` 组件与语义令牌，再由页面使用。
